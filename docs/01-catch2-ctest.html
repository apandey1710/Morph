MORPH / LESSON 01

One executable.
Three distinct jobs.

Understand what CMake, Catch2, and CTest each do. Build your first test before introducing file fixtures.

Real project examplesRunnable C++ checkpointNo custom test runner

Build, assert, run

CMake describes targets and dependencies, then generates instructions for your build tool. Catch2 is linked into the test executable and provides test cases, assertions, and a main function. CTest launches registered tests and summarizes their exit results. Installing CMake gives you CTest, not Catch2.

Give tests a home 

Morph/
├── CMakeLists.txt
├── libs/io/              # Existing production library
└── tests/
    ├── CMakeLists.txt
    └── io_tests.cpp

Keep the test executable separate from the application. It links morph::io, so it receives that library’s public includes and C++20 requirement. It does not need a window or the application’s main function.

Connect the project

Enable testing at the root, before checking BUILD_TESTING. Put the tests subdirectory after the library definitions. Replace any earlier root-level test executable block with this arrangement.

Root integration fragment 

# Root CMakeLists.txt: integration fragment, not a full replacement.
include(CTest) # Enables testing and defines BUILD_TESTING (default ON).

# Keep the existing dependency and library configuration here.
add_subdirectory(libs/io) # Keep only one copy of this existing line.

if(BUILD_TESTING)
    add_subdirectory(tests)
endif()

tests/CMakeLists.txt 

# tests/CMakeLists.txt — complete replacement for the test configuration.
include(FetchContent)
FetchContent_Declare(Catch2
    URL https://codeload.github.com/catchorg/Catch2/tar.gz/refs/tags/v3.8.1
    URL_HASH SHA256=18b3f70ac80fccc340d8c6ff0f339b2ae64944782f8d2fca2bd705cf47cadb79
)
FetchContent_MakeAvailable(Catch2)

add_executable(morph_io_tests io_tests.cpp)
target_link_libraries(morph_io_tests PRIVATE morph::io Catch2::Catch2WithMain)

list(APPEND CMAKE_MODULE_PATH "${catch2_SOURCE_DIR}/extras")
include(Catch)
catch_discover_tests(morph_io_tests)

Catch2::Catch2WithMain provides the framework and its entry point. The module path makes the fetched package’s Catch.cmake discoverable. catch_discover_tests registers named Catch2 cases with CTest after the executable is built.

Choose one registration strategy

Remove the old add_test(NAME morph_io_tests ...) registrations when adopting discovery. Keep one add_executable(morph_io_tests ...), in the tests directory. Discovery replaces the single executable-level registration; using both runs cases twice.

Start with one expectation

tests/io_tests.cpp — complete first checkpoint 

#include <catch2/catch_test_macros.hpp>
#include <vector>

TEST_CASE("a new byte buffer is empty", "[smoke]")
{
    const std::vector<unsigned char> bytes;
    REQUIRE(bytes.empty());
}

Remove your old main(); Catch2 supplies it. This deliberately simple check verifies the testing setup, not your IO functions. Replace it with the IO suite in lesson 3 once the build works.

Configure once, rebuild after edits, run 

cmake -S . -B build -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build --target morph_io_tests --parallel 2
ctest --test-dir build --output-on-failure

Run these from the Morph root. CTest does not compile changes. A successful compile also does not mean the assertions passed: the last command is what executes them. First configuration needs network access for dependencies; fetching Catch2 is skipped when testing is disabled.

With Visual Studio or another multi-configuration generator, add --config Debug to the build command and -C Debug to CTest. CMAKE_BUILD_TYPE is for single-configuration generators.

List cases; show passing output too; filter by name 

ctest --test-dir build -N
ctest --test-dir build -V
ctest --test-dir build -R readFile --output-on-failure

Use the standalone checkpoint

To try the full suite without changing Morph’s build files, download and extract the checkpoint, then run the configure/build/test commands from that directory. In this repository, use cmake -S docs/examples -B build-tutorial -DCMAKE_BUILD_TYPE=Debug, build build-tutorial, then run CTest with that same directory. It already contains a complete CMake project.

When the wiring fails

SymptomCheck this first
No tests foundEnable CTest at the root, set BUILD_TESTING=ON, build the tests, and point CTest at the correct build directory.
Cannot find io_tests.cppCreate the source beside tests/CMakeLists.txt; paths there are relative to tests/.
Duplicate main or targetRemove the hand-written main and duplicate executable definitions.
Cannot find Catch moduleAppend the fetched extras directory before include(Catch).

Try it

Change the smoke assertion to REQUIRE(bytes.size() == 1). Rebuild and run. Find the file, line, and comparison in the failure. Restore the correct expectation. Seeing both outcomes proves that you are running the executable you just built.
