Your starting point

You have an 8 × 8 grid, a player at (2.5, 1.5), and a raylib drawing loop. A dark cell means wall; an empty cell means traversable space. These lessons add one idea at a time, keeping the overhead map useful all the way to the first-person view.

The working model

Keep the raycaster on the CPU: find a wall for each ray, calculate its projected size, then let raylib draw the resulting lines or strips. Full 3D meshes and a custom GPU pipeline would obscure the geometry we are learning.

Keep these spaces separate

Space Meaning Example
World Floating-point positions on the horizontal plane. One cell is one unit. Player = (2.5, 1.5)
Map Integer indices, row before column. Bounds are checked before indexing. level[y][x]
Camera Forward depth and sideways position relative to the player. depth = dot(hit − player, forward)
Screen Pixels from the top-left. +x right, +y down. pixelX = offsetX + worldX × scale

On our overhead map, world +x points right and +y points down. A positive rotation is clockwise. Walls have height 1 world unit. For projection, the eye is halfway up the wall, the camera is level, and screen pixels are square.

Before your first ray

In the current map loop, use y < mapHeight and x < mapWidth. The reversed bounds happen to work for a square map, but fail when the dimensions differ. Draw all the cells first, then the rays, then the player once. Drawing the player inside the cell loop repeats the work and lets later cells paint over it.

The earlier expression playerScreen.x + 0.75f * pixelsPerCell chooses a visual direction-line endpoint. It does not find a wall. In lesson 1, the endpoint comes from an actual grid intersection.

How to use the notebook

First move the controls and predict what will happen. Then work through the equations and focused snippets. Finally, run the complete checkpoint and try the observable checks at the end. The browser labs mirror the C++ math; they are teaching diagrams, not a replacement for implementing it yourself.

No package installation is needed to read the site. All pages, styles, scripts, and examples are served locally from this repository, with no analytics or third-party assets.
