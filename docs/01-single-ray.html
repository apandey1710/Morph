01 / A ray is a question

Imagine pointing a laser from the player. You want to know which wall it reaches first and exactly where it touches. A ray describes every possible point along that laser, starting at the player and extending forward.

P(t) = O + tD,   t ≥ 0
x(t) = origin.x + t × direction.x
y(t) = origin.y + t × direction.y

O is the origin in world units. D is the direction vector. t is a nonnegative parameter that scales that vector. If D has length 1, t is distance in world units. If D is longer or shorter, t is not distance: the traveled length is t × length(D).

For O = (2.5, 1.5) and D = (1, 0), a value of t = 0.5 gives P = (3, 1.5). The ray has reached the right edge of its starting cell. Our first wall is at x = 7, so the eventual hit is (7, 1.5), in cell (7, 1), at t = 4.5.

Why not keep adding 0.01?

Fixed-size steps repeatedly sample points inside the same cell. Large steps can skip a thin passage through a wall cell near a corner; small steps do extra work and still approximate the boundary. DDA visits the boundaries themselves, so every step is a meaningful cell crossing.

02 / Race the next two boundaries

DDA stands for digital differential analysis. In this grid traversal, we keep track of when the ray will next cross a vertical grid line and when it will next cross a horizontal one. Whichever happens first tells us which neighboring cell to inspect.

Crossing a vertical line changes the cell's x index, so we call it an X-side crossing. Crossing a horizontal line changes its y index, a Y-side crossing. The names refer to the changing coordinate, not the visual orientation of the line.

deltaX = |1 / direction.x|
deltaY = |1 / direction.y|

These are increments in t, not automatically world distances. Why the reciprocal? Adjacent vertical grid lines are one world unit apart. From Δx = Δt × direction.x, a change of one cell gives |Δt| = |1 / direction.x|.

For the first crossing, use only the remaining fraction of the starting cell. When moving right, the next vertical boundary is at cellX + 1; when moving left, it is at cellX.

Formula fragment · the complete implementation handles zero components 

// Finite, nonzero direction.x assumed in this isolated formula.
const int stepX = direction.x < 0.0f ? -1 : 1;
const double gapX = direction.x < 0.0f
    ? origin.x - cellX
    : cellX + 1.0 - origin.x;
const double nextX = gapX * deltaX;

Repeat the same calculation for y. After crossing X, advance cellX by stepX and add deltaX to the next-X time. Leave the next-Y time alone. The opposite applies after crossing Y.

A diagonal example, by hand

Use O = (2.5, 1.5) and the unit direction D = (0.8, 0.6). Then deltaX = 1.25 and deltaY ≈ 1.667. The initial half-cell gaps give nextX = 0.625 and nextY ≈ 0.833.

Step Compare Visit Result
1 0.625 < 0.833 X → cell (3, 1) Empty; nextX becomes 1.875
2 0.833 < 1.875 Y → cell (3, 2) Wall; stop at t ≈ 0.833

The hit position is (2.5, 1.5) + 0.833… × (0.8, 0.6) = (3.166…, 2.0). You hit the top edge of the wall in row 2. Try a direction near 37° in the lab to see this path.

03 / Return the geometry, not a drawing

Keep traversal independent of rendering. The following complete DDA helper returns the hit cell, crossed side, parameter t, and world-space point. It takes a rectangular map by reference, so C++ infers the dimensions. Nonzero cells are solid. The function requires a finite origin inside an empty cell and a finite, nonzero direction; it returns std::nullopt for invalid input, a solid origin, or a ray that exits the map.

Complete helper from raycaster.hpp · requires raylib.h, cmath, limits, optional 

enum class Side
{
    X, // Crossed a vertical grid line: the cell's x index changed.
    Y  // Crossed a horizontal grid line: the cell's y index changed.
};

struct RayHit
{
    int cellX;
    int cellY;
    Side side;
    double t; // Parameter in origin + t * direction, not always ray length.
    Vector2 position;
};

// Accept a map by reference so dimensions are inferred, including non-square maps.
// Empty origin required. Invalid rays, solid origins, and map exits return nullopt.
template <int Height, int Width>
std::optional<RayHit> castRay(const int (&map)[Height][Width],
                              Vector2 origin, Vector2 direction)
{
    if (!std::isfinite(origin.x) || !std::isfinite(origin.y) ||
        !std::isfinite(direction.x) || !std::isfinite(direction.y) ||
        (direction.x == 0.0f && direction.y == 0.0f) ||
        origin.x < 0.0f || origin.x >= Width ||
        origin.y < 0.0f || origin.y >= Height)
    {
        return std::nullopt;
    }

    int cellX = static_cast<int>(std::floor(origin.x));
    int cellY = static_cast<int>(std::floor(origin.y));
    if (map[cellY][cellX] != 0)
    {
        return std::nullopt;
    }

    const double infinity = std::numeric_limits<double>::infinity();
    const int stepX = direction.x < 0.0f ? -1 : 1;
    const int stepY = direction.y < 0.0f ? -1 : 1;
    const double deltaX = direction.x == 0.0f ? infinity :
        std::abs(1.0 / direction.x);
    const double deltaY = direction.y == 0.0f ? infinity :
        std::abs(1.0 / direction.y);

    // Guard zero components explicitly: 0 * infinity would produce NaN.
    double nextX = direction.x == 0.0f ? infinity :
        (direction.x < 0.0f ? origin.x - cellX : cellX + 1.0 - origin.x) * deltaX;
    double nextY = direction.y == 0.0f ? infinity :
        (direction.y < 0.0f ? origin.y - cellY : cellY + 1.0 - origin.y) * deltaY;

    // Each step changes one cell index monotonically; this bound covers map exit.
    for (int crossing = 0; crossing < Width + Height; ++crossing)
    {
        double t;
        Side side;
        if (nextX <= nextY) // Exact corner ties deliberately visit X first.
        {
            t = nextX;
            nextX += deltaX;
            cellX += stepX;
            side = Side::X;
        }
        else
        {
            t = nextY;
            nextY += deltaY;
            cellY += stepY;
            side = Side::Y;
        }

        if (cellX < 0 || cellX >= Width || cellY < 0 || cellY >= Height)
        {
            return std::nullopt;
        }
        if (map[cellY][cellX] != 0)
        {
            return RayHit{cellX, cellY, side, t,
                Vector2{static_cast<float>(origin.x + t * direction.x),
                        static_cast<float>(origin.y + t * direction.y)}};
        }
    }
    return std::nullopt;
}

Edge cases are part of the algorithm

  • A zero component: an exactly horizontal ray never crosses a horizontal boundary. Set its next-Y time to infinity. Handle that branch explicitly: multiplying a zero gap by infinity produces NaN, which breaks comparisons.
  • Map boundaries: check the new cell before indexing. Even a bordered map should not be trusted to prevent invalid memory access.
  • Starting on a grid line: moving into the cell on the negative side can give t = 0. That is a valid boundary hit, not necessarily a bug.
  • Corner ties: this implementation deliberately visits X first when nextX equals nextY. If that cell is empty, Y is visited at the same t. It does not inspect the other side-adjacent cell. This deterministic visual convention is not a conservative collision rule; a collision system may need to inspect both neighbors.
  • Near ties: floating-point rounding can decide which side wins. Avoid adding a broad epsilon that changes which walls are hit. A stricter corner policy can be a later experiment.
  • Termination: each cell index moves only in one direction. Width + Height crossings are enough to hit a wall or leave this finite map.

04 / Put the hit back on the map

Now convert the world hit into screen pixels. The same conversion must be used for the player and the hit. These fragments use your existing offsetX, offsetY, and pixelsPerCell constants.

Integration fragments · place the helper outside main and the drawing code inside the frame 

Vector2 toScreen(Vector2 world)
{
    return Vector2{
        offsetX + world.x * pixelsPerCell,
        offsetY + world.y * pixelsPerCell
    };
}

// Inside the drawing loop, after all map cells have been drawn:
const Vector2 direction{1.0f, 0.0f};
const auto hit = castRay(level, playerPosition, direction);
if (hit)
{
    const Color color = hit->side == Side::X ? SKYBLUE : ORANGE;
    DrawLineV(toScreen(playerPosition), toScreen(hit->position), color);
    DrawCircleV(toScreen(hit->position), 3.0f, color);
}
DrawCircleV(toScreen(playerPosition), 5.0f, WHITE);

The line now ends at a wall because the level geometry chose its endpoint. Its pixel length is a consequence of the hit distance and drawing scale, rather than an arbitrary visual length.

05 / Make the result falsifiable

  1. Face east: expect cell (7, 1), an X-side hit at (7, 1.5), and t = 4.5.
  2. Face north with D = (0, −1): expect cell (2, 0), a Y-side hit at (2.5, 1), and t = 0.5.
  3. Change D from (1, 0) to (2, 0). The hit point should stay the same while t halves to 2.25. This reveals why t is not always length.
  4. Remove a border wall in a temporary map. A ray through the opening should return no hit without indexing outside the map.
  5. Change the drawing scale. World hit coordinates must stay the same.
Checkpoint

You are ready for a camera when one ray reliably stops at the first wall, horizontal and vertical rays work, and changing direction magnitude does not change the hit point.
