Choose observable promises

A byte is one unit of binary storage. The payload below includes a zero, line-ending bytes, and values above 127. Those catch assumptions that file contents are ordinary text. A zero byte is data, not an instruction to stop reading. 

std::vector<std::byte> expected{
    std::byte{0x00}, std::byte{0x0A}, std::byte{0x0D},
    std::byte{0x7F}, std::byte{0x80}, std::byte{0xFF}
};

The current writer accepts std::span<std::byte>, so its input vector must be mutable. A read-only span would better describe a writer that only observes its input, but that API improvement is separate from designing these tests.

Give each function an independent witness

For a reader test, create the fixture with a standard output stream. For a writer test, inspect the result with a standard input stream. If both Morph helpers applied the same reversible transformation, a round trip could pass while the actual on-disk format was wrong.

Fragment from io_tests.cpp — helper definitions are in the download 

TEST_CASE("readFile preserves binary bytes", "[io][read]")
{
    TempDirectory directory;
    const auto path = directory.file("binary.bin");
    const auto expected = payload();
    seed(path, expected);

    const auto actual = morph::io::readFile(path);

    REQUIRE(actual == expected);
}

seed creates known contents and checks the stream after closing. inspect reads one char at a time, converts through unsigned char to preserve high-bit values, and distinguishes end-of-file from a bad stream. These helpers use the standard library directly; they do not call the Morph functions.

Own the temporary directory

A fixture is the setup a test needs: here, a private directory and perhaps an initial file. Do not use a fixed shared filename, a real asset, or the repository’s working files. CTest can run cases concurrently, and a previous failed run must not decide the next result.

temp_directory.hpp — complete helper 

#pragma once
#include <filesystem>
#include <random>
#include <stdexcept>
#include <string>
#include <system_error>
#include <utility>

// Own only a directory that this object successfully created.
class TempDirectory
{
public:
    TempDirectory()
    {
        std::random_device random;
        const auto base = std::filesystem::temp_directory_path();
        for (int attempt = 0; attempt < 100; ++attempt)
        {
            auto candidate = base / ("morph-io-test-" + std::to_string(random())
                + "-" + std::to_string(random()));
            // Atomic creation avoids reusing another test's directory.
            if (std::filesystem::create_directory(candidate))
            {
                path_ = std::move(candidate);
                return;
            }
        }
        throw std::runtime_error("Could not create a unique test directory");
    }

    ~TempDirectory()
    {
        std::error_code ignored;
        std::filesystem::remove_all(path_, ignored);
    }

    TempDirectory(const TempDirectory&) = delete;
    TempDirectory& operator=(const TempDirectory&) = delete;

    std::filesystem::path file(const std::string& name) const
    {
        return path_ / name;
    }

private:
    std::filesystem::path path_;
};

The constructor reserves a directory by creating it, rather than merely guessing an unused name. The 100 attempts bound retries for name collisions; filesystem errors propagate immediately. The object owns only a directory it successfully created. Copying is disabled so two owners cannot delete the same directory.

This is RAII: resource acquisition is initialization. The object acquires its directory during construction and releases it during destruction, including when a fatal assertion unwinds the test. Cleanup uses the error-code overload so its destructor cannot throw. A process crash or cleanup permission error may still leave a directory behind; this helper is for ordinary test isolation, not a security boundary.

Test the overwrite, not just creation

Fragment from io_tests.cpp 

TEST_CASE("writeFile truncates a longer file", "[io][write]")
{
    TempDirectory directory;
    const auto path = directory.file("overwrite.bin");
    seed(path, payload());
    std::vector<std::byte> shorter{std::byte{0x42}};
    morph::io::writeFile(path, shorter);
    REQUIRE(inspect(path) == shorter);
    CHECK(std::filesystem::file_size(path) == 1);
}

Writing the same six bytes over six bytes would not reveal retained trailing data. Deliberately shrink the payload. That one choice makes the test discriminate between overwriting and appending.

Know what this suite does not prove

A real limitation in the current writer

The teaching snapshot checks whether opening succeeded but does not check stream state after writing or closing. The eight cases can pass while a disk-full error goes unreported. A successful open is not a guarantee of a successful write.

A future fix should explicitly detect write and close failures, with a targeted failure test. Portable ways to force those errors are limited. Permission tests vary by operating system and can pass unexpectedly under privileged accounts; disk exhaustion is disruptive. Do not make either a prerequisite for this beginner suite.

Likewise, the suite does not simulate a file changing between size measurement and reading, and successful close is not a guarantee of durability through power loss. Add tests for those promises only if your API needs to make them. Avoid refactoring the reader into a mockable stream architecture just to cover every branch at this stage.
